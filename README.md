# AI기본법 컴플라이언스 체커 (RAG)

법무팀 없는 AI 기업이 기획 단계에서 **"우리 서비스에 AI기본법상 어떤 의무가 있는지"**를 **근거 조문과 함께** 확인하는 RAG.

Baseline부터 6개 Pipeline을 같은 질문셋으로 측정해 비교하고, **효과가 없던 개선은 근거를 적어 폐기**했다.

```
Baseline (글자수 Chunk + Similarity)   Recall@4 0.611 / MRR 0.639
Final    (조 단위 + ParentDoc           Recall@4 0.722 / MRR 0.778
          + Hybrid BM25 + Route)        (+18% / +22%)
```

| Pipeline | Recall@4 | MRR | 판단 |
|---|---|---|---|
| 1. Baseline | 0.611 | 0.639 | 조문 중간이 잘림 |
| 2. + 조 단위 Chunk | 0.556 ↓ | 0.444 ↓ | **역효과 — 단독 적용 폐기** |
| 3. + ParentDocument | 0.611 | 0.676 | 작은 조각으로 검색, 조 전체 반환으로 회복 |
| 4. + Hybrid (BM25) | 0.722 | 0.704 | Recall 기여 최대 |
| 5. + Rewrite·Route | 0.611 | 0.778 | **Rewrite는 트레이드오프 — 최종에서 제외** |
| **6. Final (Hybrid + Route)** | **0.722** | **0.778** | 채택 |

평가 조건과 질문별 결과는 [results/evaluation.md](results/evaluation.md), 설계 근거는 [results/design.md](results/design.md)에 있다.

## 이 프로젝트에서 실제로 판단한 것

**1. "구조를 살리면 좋아진다"는 가정이 틀렸다**

조문 경계로 Chunk를 나누면 당연히 나아질 줄 알았는데 Recall이 0.611 → 0.556으로 떨어졌다. 긴 조문을 통째로 임베딩하면 의미가 희석된다. ParentDocument(작은 조각으로 검색 → 조 전체 반환)로 바꾸고 나서야 MRR이 0.444 → 0.676으로 회복됐다.

**2. 지표가 오른 개선을 뺐다**

Rewrite는 MRR을 최고치(0.778)로 올렸지만 Recall을 0.722 → 0.611로 떨어뜨렸다. 원래 질의와 재작성된 질의가 Top-4를 나눠 가지기 때문이다. Top-K가 고정된 조건에서는 손해라고 판단해 Rewrite를 빼고, 효과가 분명한 Route("제N조" 직접 조회)만 남겼다. 그 결과 "제34조는 무슨 내용이야?" 질문의 정답 조항이 4위 → 1위가 됐다.

**3. 남은 실패를 원인까지 추적했다**

"고영향 인공지능이 정확히 뭐야?"는 6개 Pipeline 전부에서 실패했다. 디버깅해 보니 FAQ의 질문 문장이 거리 0.50으로 가장 가까웠고, 정답인 정의 조항은 0.80으로 멀었다. **질문형 문장끼리 가깝고 선언문(`"…"이란 …을 말한다`)은 멀다** — 검색 실패가 아니라 질문↔조문 문체 차이 문제다. 다음 개선 후보를 HyDE로 잡은 근거다.

**4. 구현 중 찾은 버그**

- Rewrite 결과를 순위 교차로 병합 → 하위 질의가 3개면 각 질의의 1위만 Top-4에 들어감 → **RRF 병합으로 변경**
- 중복 제거가 마지막 등장 위치 기준으로 정렬 → Route로 1위에 올린 조문이 뒤로 밀림 → **첫 등장 순서 유지로 수정** (MRR 0.704 → 0.778)

## 문제 정의

- AI기본법은 추상적인 표현으로 쓰여 있고, 법률·시행령·가이드라인에 흩어져 있으며, 조문끼리 서로 참조한다.
- 사용자는 사업 언어("채용 솔루션", "벌금")로 묻는데, 법은 법률 언어("채용 판단에 활용되는 고영향 인공지능", "과태료")로 쓰여 있다.
- 목표: 관련 조문을 찾아 인용하며 답하고, 근거가 없으면 답하지 않고, 해당 여부는 "가능성"으로만 표현한다.

생성 결과도 이 기준으로 확인했다. "이력서 자동 선별 채용 솔루션도 규제 대상?"에는 시행령 제2조를 근거로 "해당할 가능성이 높습니다"라고 답했고(개선 전에는 무관한 제35조를 근거로 들었다), "미국 AI 규제와 비교하면?"에는 "제공된 문서에서 확인할 수 없습니다"로 답했다.

## 구조

![Pipeline](results/pipeline.png)

| 항목 | 값 |
|---|---|
| Embedding / LLM | `text-embedding-3-small` / `gpt-4o-mini` (temperature=0) |
| Vector Store | FAISS |
| Retriever | ParentDocument + BM25 Hybrid + Route |
| Top-K | 4 (모든 Pipeline 동일) |
| 질문셋 | 고정 10개 (Retrieval 평가는 문서에 없는 질문을 뺀 9개) |

## 실행

```bash
uv sync
cp .env.example .env   # OPENAI_API_KEY 입력
uv run --locked python src/capstone_compare.py
```

Python 3.11, uv 필요. 출력은 질문별 6개 Pipeline의 Top-4와 Recall/RR, 요약 표, 최종 Pipeline의 답변 3개다. 전체 실행 로그는 [results/run_log.txt](results/run_log.txt)에 있다.

## 데이터

`data/`의 법률(11개 조)·시행령(7개 조)·FAQ(6개), 총 6,541자는 **실제 법률 구조를 참고해 작성한 실습용 샘플**이다. 조문 번호와 기준이 실제와 다를 수 있다. 실제 적용 시 국가법령정보센터 Open API로 교체해야 한다(법률 54개 조 규모로 늘어나므로 정답 라벨 재매핑과 재평가가 필요하다).

## 한계

- **질문셋 9개** — 표본이 작아 지표 변동이 크다. 20개 이상으로 확대 필요.
- **복합 질문의 두 번째 주제 누락** — "고지 의무 + 과태료"에서 제43조를 놓쳤고, 그대로 답변 누락으로 이어졌다. 하위 질의별 Top-k 할당 또는 Reranker가 필요하다.
- **교차참조를 따라가지 못한다** — 제34조가 제33조를 참조해도 자동 확장하지 않는다.
- **문체 차이** — 위 3번 참조. HyDE 적용 예정.
- 법률 자문이 아니다. 모든 답변에 면책 문구를 붙인다.
