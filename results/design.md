# 설계 문서 — AI기본법 컴플라이언스 체커

## 1. 해결하려는 문제

> 법무팀 없는 AI 기업이 **기획 단계에서 AI기본법 해당 여부와 필요 조치를 근거 조문과 함께** 확인할 수 있게 한다.

- AI기본법(2026.1 시행)은 "고영향 인공지능"처럼 추상적인 표현으로 쓰여 있어서, 현업은 "우리 서비스가 해당되는지"부터 판단하기 어렵다.
- 원칙은 법률에, 구체적 기준은 시행령에, 사례는 FAQ에 흩어져 있다. 조문끼리도 "제33조에 따른 …"처럼 서로 참조한다.
- 일반 LLM은 최신 법을 모르거나 조항을 지어내고, 로펌 자문은 비싸고 느리다.
- **핵심 난점: 사용자는 사업 언어로 묻고("채용 솔루션", "벌금"), 법은 법률 언어로 쓰여 있다("채용 판단에 활용되는 고영향 인공지능", "과태료").**

### 3.4 사용 방식과 재현

- **라벨:** 각 Chunk에 `법 제N조` / `령 제N조` / `가이드 QN` 라벨을 붙여, 질문별 정답 라벨이 Top-4 안에 있는지로 평가했다. Baseline Chunk는 시작 위치로 조항을 역추적해 같은 기준으로 비교했다.
- **API 사용량 (1회 실행 기준):**
  - Embedding: 133개 Chunk(50 + 24 + 59)
  - LLM: Rewrite 10회 + 답변 3회 (`gpt-4o-mini`)
- **재현:** `data/law.txt`, `data/decree.txt`, `data/guideline.txt`를 줄 시작이 `제N조(제목)` 또는 `QN.`인 형식으로 두면 코드 수정 없이 실행된다.
- **실제 원문으로 교체:** 국가법령정보센터 Open API 또는 원문 저장으로 같은 형식을 만들면 된다. 조항 번호가 바뀌면 질문셋의 정답 라벨도 다시 확인해야 한다.

## 5. 검색 개선 전략과 선택 이유

진단 → 선택 순서로 하나씩 적용하고, 매 단계를 같은 질문셋으로 측정했다.

| 단계 | 관찰된 문제 | 적용한 전략 | 교재 대응 |
|---|---|---|---|
| 2 | 글자 수 Chunk가 조문 중간을 자르고, 어느 조인지 정보가 사라짐 | 조(條) 단위 Chunk + 출처 머리글 | Chunk 설계 |
| 3 | 조 단위로 자르자 긴 조문(제2조 정의, 10개 호)이 임베딩에서 희석됨 → **오히려 성능 하락** | ParentDocument(항·호 단위로 검색, 조 전체를 반환) + child별 조 머리글 | ParentDocumentRetriever |
| 4 | "결과물 표시", "과태료"처럼 정확한 법률 용어는 Dense 검색이 놓침 | BM25 + Vector Hybrid. 한국어 조사 처리를 위해 글자 2-gram 사용 | BM25 / Hybrid / Ensemble |
| 5 | 사업 언어("벌금", "그림 AI")와 법률 언어가 다름 | LLM Query Rewrite(법률 용어 변환 + 복합 질문 분해) + RRF 병합 | Query Rewrite / Decomposition |
| 5 | "제34조"를 물어도 다른 조문의 "제34조에 따른…" 참조가 점수를 나눠 가짐 | "제N조" 정규식 → 해당 조 직접 조회 | Routing |
| **최종** | Rewrite는 순위(MRR)는 올렸지만 Top-4 안에서 정답을 밀어내 Recall이 떨어짐 | **Hybrid + Route 채택, Rewrite 제외** | 트레이드오프 판단 |

## 6. 평가 질문과 평가 방법

- **질문 10개 (고정):** 명확 1, 키워드 1, 표현 차이 5, 교차참조 1, 복합 1, 문서에 없음 1. 각 질문마다 **정답 근거 조항 라벨**(예: `["법 제31조", "령 제3조"]`)을 달았다.
- **Retrieval 평가:** 문서에 없는 질문은 제외한 9개로 측정한다.
  - Recall@4: 정답 조항 중 Top-4 안에서 찾은 비율
  - MRR: 첫 정답 조항 순위의 역수
  - 전부 찾은 질문 수
  - Baseline Chunk는 시작 위치로 조항을 역추적해 라벨을 붙이므로, 모든 Pipeline을 같은 기준으로 비교할 수 있다.
- **Generation 평가:** 최종 Pipeline으로 아래 세 가지를 확인한다.
  1. 근거 조항을 실제 출처에 맞게 인용하는가
  2. 해당 여부를 단정하지 않는가
  3. 문서에 없는 질문에 "확인할 수 없습니다"라고 답하는가

## 7. 예상 한계와 보완 방법

| 한계 | 보완 방법 |
|---|---|
| 질문과 조문의 **문체 차이**: "고영향 AI가 뭐야?"는 모든 Pipeline에서 실패. FAQ의 질문 문장이 더 가깝게 잡힘 | HyDE(가상의 조문 형태 답변을 만들어 검색), FAQ 질문 부분 가중치 조정 |
| 복합 질문에서 두 번째 주제(과태료)를 놓침 | 분해한 하위 질의별로 Top-k 자리를 나눠 주는 방식, 또는 Reranker |
| 교차참조 조문(제34조 → 제33조)을 자동으로 따라가지 못함 | 본문 속 "제N조" 참조를 파싱해 1-hop 확장 |
| 질문 9개뿐이라 질문 1개가 Recall 0.11만큼 움직임 | 질문셋을 20개 이상으로 확장 |
| 샘플 문서 | 국가법령정보센터 원문으로 교체(같은 형식이면 코드 수정 불필요) |
| 법적 판단 | "가능성"으로만 표현하고 면책 문구 고정. 최종 판단은 전문가 |
